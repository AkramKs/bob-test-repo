# Code Quality Rules for AI Pull Requests

## 1. Language & Style Adherence
- Match the existing codebase conventions (naming, indentation, quotes, imports) observed in `main.py` and any other Python files.
- All endpoint functions must be `async def` unless a synchronous-only operation is required.
- Use type hints for all function signatures and Pydantic model fields.

## 2. Required Practices (verified tools)
- **Testing**: Use `pytest` with `httpx`-based `TestClient` (from `fastapi.testclient`) for endpoint tests.  
  Run `pytest -v` and ensure **all tests pass** before opening a PR.
- **API Design**:
  - Request/response bodies must use **Pydantic models** (`BaseModel` from Pydantic).
  - Use FastAPI’s `HTTPException` for error responses (no bare `return` with error dicts).
  - Define path parameters, query parameters, and request bodies with proper Pydantic validation.
- **Database Access**: If SQLAlchemy is used (as per `requirements.txt`), all queries must go through the **ORM models**, never raw SQL.
- **Static files**: The project includes `static/index.html`; never hard-code paths—use `app.mount` or `StaticFiles` if serving static content.

## 3. Forbidden Patterns
- Do not ignore errors; every exception must be caught and returned as a proper HTTP response (or allowed to bubble up with a global handler).
- Never return unvalidated dictionary responses—use Pydantic model `.dict()` or FastAPI’s automatic model serialization.
- Do not introduce new dependencies without adding them to `requirements.txt` with a pinned version.
- Do not modify the core product schema fields (`name`, `price`, etc.) without updating the README and all related endpoints.

## 4. Pull Request Checklist
- [ ] All tests pass: `pytest -v` (no failures, no skips).
- [ ] The API can start with `uvicorn main:app` without import or runtime errors.
- [ ] New endpoints are documented in the README (if the list changes).
- [ ] No new dependencies added without a pinned version in `requirements.txt`.
- [ ] Existing `static/index.html` still loads correctly if the server serves static files.
- [ ] Pydantic models and SQLAlchemy models are consistent (if both are used).
- [ ] PR description references the ticket (e.g., `ticket-34.md`) if applicable.
